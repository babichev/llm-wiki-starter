# Как помочь проекту

Полезны исправления ошибок, понятные объяснения для новичков и улучшения, проверенные на вымышленных данных.

Перед предложением прочитай [README](README.md) и проверь, нет ли похожего Issue или Pull Request. Для небольшой правки достаточно объяснить, что было неудобно и как изменится результат. Крупное изменение сначала опиши в Issue.

## Сообщить об ошибке

Укажи версию комплекта, ОС, версию Python при работе со скриптами, шаги воспроизведения, ожидаемый результат и фактическую ошибку. Используй небольшой вымышленный пример.

Не прикладывай свою настоящую базу, письма, транскрипты, контакты, токены, резервные копии или скрытую папку состояния. Перед вставкой лога убери личные пути и секреты. Для уязвимости используй [SECURITY.md](SECURITY.md).

## Предложить изменение

Работай в отдельной ветке и меняй только то, что относится к задаче. Сохраняй совместимость существующих заметок, ручной текст, историю источников и границы разрешений. Не добавляй сетевые обращения, платные зависимости или передачу данных без ясной необходимости и описания.

Если меняешь исполняемый код, проверь наблюдаемое поведение на отдельной тестовой базе. Для простой правки текста достаточно проверить смысл и ссылки.

Из корня комплекта:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
python3 tooling/release.py scan
```

В Pull Request объясни проблему, результат, выполненные проверки и существенные ограничения. Для нового skill укажи, когда он применяется, нужные входные данные и пример проверки результата. Не выдавай структурную проверку за подтверждение качества любых будущих ответов.

Собственный вклад предлагается на условиях [MIT](LICENSE). Не копируй чужие тексты, код или assets без совместимой лицензии и нужной атрибуции. В проекте действует [кодекс общения](CODE_OF_CONDUCT.md).
