# Запуск LLM Wiki

Результат — доступная владельцу база с заполненным минимальным контекстом, рабочей навигацией и честным статусом подключений. Пустые папки и предложенное расписание сами по себе не означают готовую систему.

## Сначала выбери доступный режим

Выясни, может ли среда читать и менять постоянные локальные файлы. При наличии — используй явно выбранный пользователем путь vault, а при его отсутствии предложи один путь. Для уже существующей базы прочитай `AGENTS.md`, `second-brain-home.md`, `system/config.json` и минимальные активные страницы. Не создавай запасную базу при ошибке доступа и не перезаписывай её шаблоном.

Если есть только обычный веб-чат, подготовь скачиваемые Markdown-файлы и инструкции для проекта/подключённого хранилища. Не изображай установку локальных skills, постоянную запись или автоматический доступ к компьютеру. Доступные функции зависят от среды и аккаунта; проверь их фактически.

## Настройка под человека

Прочитай `prompts/START-HERE.ru.md` из стартового комплекта, если он доступен. Уточни одним компактным блоком только недостающие ответы, влияющие на результат: язык и обращение, актуальные цели, сферы жизни, ограничения времени, текущие источники, путь хранения и часовой пояс. Подключения и фоновые задачи настраивай после рабочего ручного цикла. Не проси секреты в чат и не переноси чужой личный контекст из примера.

Для новой локальной базы используй `scripts/wiki.py --help` из комплекта и его недеструктивный `init`; скрипт должен отказаться от перезаписи. Затем открывай установленный `system/scripts/wiki.py` внутри vault. Стандартный init устанавливает все шесть core skills этого комплекта в создаваемый vault. Дополнительные внешние skills выбирай и устанавливай отдельно по задаче; общесистемную установку, плагины и платные сервисы не считай следствием создания папки.

Заполни профиль, текущий фокус, принципы решений, голос, реестр источников и статус установки. Неизвестное оставляй неизвестным; предположения о человеке сохраняй как гипотезы. Нужный контекст распределяй по каноническим страницам, не копируй весь профиль в каждую инструкцию.

## Проверка готовности

Проведи один цикл на нейтральной заметке: сохранение источника → каноническое знание → ссылка → проверка → поиск ответа по базе. Перезапуск не должен порождать дубли. Проверь, что `inbox/` и `raw/` трактуются как данные, ручные заметки сохраняются, backup можно прочитать, а недоступный источник отмечается как недоступный.

Отдельно перечисли: что создано, что проверено, что подключено, что лишь подготовлено и что требует участия пользователя. Готовую автоматизацию подтверждай её ID, расписанием, часовым поясом и наблюдаемым пробным запуском. Предложенный текст задачи не является созданной задачей.

Рабочая база по умолчанию приватна. Публичным может быть только отдельно проверенный обезличенный шаблон. Не публикуй, не отправляй сообщения и не принимай внешние обязательства без соответствующего поручения.
