# Обновление LLM Wiki

Результат — актуальный связанный канон. Коллекция пересказов без отражения изменений в Wiki не закрывает задачу.

1. Прочитай AGENTS, главную, конфигурацию, setup-status и предыдущий отчёт. Проверь фактические tools и разрешённый scope. Зафиксируй run и получи writer lease. При чужой lease не начинай вторую запись.
2. Сначала обработай доступные локальные входящие материалы. Для каждого подключённого источника сканируй изменения с перекрытием, сохраняй stable IDs и версии. При первом запуске согласуй ограниченный период. Если API использует pagination, проходи до фактического конца или сохраняй курсор и частичное покрытие. Не сдвигай watermark за непройденные страницы.
3. Сохраняй точный полученный материал через ingest. Не удаляй originals. Не копируй OTP/credentials и нерелевантные личные сообщения. Если источник неполон, укажи coverage. Подключённое приложение не означает доступ ко всему аккаунту.
4. Прочитай pending, сопоставь с каноном, выдели новые факты, claims, решения и конфликты. Приоритет — текущие проекты и живые решения, но часть доступного времени оставь на backfill. Лимит нагрузки не является поводом пометить остаток выполненным.
5. Перечитай целевые файлы, сохрани manual edits и approved wording. Обнови минимальный набор страниц, существенные связанные сводки и даты достоверности. Утверждения подкрепи источником. Конфликт — в review queue, изменение личного правила требует прямого основания.
6. Проверь readback и ссылки. Mark processed только после отражения материала. Audit, индекс только в generated block, health и backup по [[playbooks/health]]. При существенной ошибке не маскируй её общим успехом.
7. Сохрани полный отчёт в system/runs, краткую запись change-log, остаток и точку продолжения. Заверши lease. Даже при сбое источника продолжай независимую доступную работу и отчитайся о частичном охвате.

Скрипт выполняет учёт и проверки, смысловой синтез делает агент. Повтор запуска с теми же версиями не должен создавать дубли. История источника не переписывается. Изменившийся источник возвращается на анализ.

В уведомлении нужны 1–3 значимых изменения или связки, необходимые действия, существенные ограничения и ссылка на полный отчёт. При отсутствии значимых изменений молчание зависит от возможностей scheduler. Не обещай его там, где среда всегда показывает ответ.

Git push, сообщения и новые расписания не входят в этот процесс без отдельного действующего разрешения. Если удалённая копия разрешена, отправляй только свой проверенный набор, сверяй удалённые файлы, не включай чужие правки.
